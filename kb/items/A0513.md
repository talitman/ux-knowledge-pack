## סיכום

- **הרעיון:** **Spec-Driven Development**. הספציפיקציה היא מקור האמת, והקוד נגזר ממנה. מפרידים בין "מה ולמה" לבין "איך".
- **שלבים (פרקים):**
  - 11:10 **Constitution:** עקרונות לא ניתנים למשא ומתן (טסטים, ספריות, סגנון).
  - 15:25 **`/specify`:** מתארים את המוצר והמשתמשים, **בלי** טכנולוגיה. נוצר spec.md עם user stories ו-acceptance criteria. מסמנים אי-בהירויות ("NEEDS CLARIFICATION").
  - 24:00 **`/plan`:** סטאק, ארכיטקטורה, data model, contracts ו-research.
  - 31:06 **`/tasks`:** פירוק למשימות קטנות שאפשר לבדוק, עם סימון מקביליות.
  - 34:28 **Implement:** הסוכן (Copilot, Claude Code, Gemini CLI) מבצע.
  - 36:24 תוצאות.
- **התקנה:** `uvx --from git+https://github.com/github/spec-kit.git specify init <project>`.
- **קישורים:** [github/spec-kit](https://github.com/github/spec-kit), ו[בלוג](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/).
- דומה לגישת Task Master ([A0224](A0224.md)) ו-Kiro specs.

**מהתמלול / מהווידאו:**
- **מהתמלול (Den Delimarsky, מתחזק Spec Kit, תוספות):**
  - 16.3k כוכבים שבוע אחרי השחרור. "ב-Microsoft אנחנו מאוד בעד spec-driven development". זו התשובה ל"בורות הארנב" של vibe coding: קוד, מימוש ועיצוב שהם "לא בדיוק מה שרציתם".
  - **התקנה:** `uvx` ישירות מהריפו (עוד לא ב-PyPI). אפשר גם בלי CLI: מורידים מה-Releases את ה-zip לסוכן ולסוג הסקריפטים (PowerShell או bash) ומחלצים לפרויקט. נוצרת תיקיית `.specify` (memory, scripts, templates) ופרומפטים ב-`.github`.
  - **בבחירת סוכן:** Copilot, Claude Code, Gemini CLI, Cursor (נוסף באותו יום). הסקריפטים **דטרמיניסטיים** (ענפי git, JSON metadata) "כדי לא להסתמך על ה-LLM לחבר דברים".
  - **הדגמה:** אתר פודקאסט ("pod site") ב-VS Code במצב agent. אם `/specify` לא מופיע, "אתם בתיקייה הלא נכונה, רמה אחת מעל". בסוף `npm run build` ו-`npm run dev`. בדיקת Lighthouse נכשלה כי Chrome לא היה מותקן.
  - **בקשה לקהילה:** לפתוח issues עם הקשר, ולא PR ש"הופך את הכל ל-MCP server" בלי לדבר קודם.
