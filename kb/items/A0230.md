## סיכום

- **השאלה (כנראה):** מה המידע האופטימלי שצריך לתת ל-LLM כדי שייצר קוד שמתקמפל, תואם סגנון ומכבד תלויות אמיתיות (ב-monorepo עם Nx/Bit)?
- **הרשימה, מהחשוב ביותר:**
  1. **High-level intent** (2–3 פסקאות): מה המוצר עושה, למי, ואילוצים.
  2. **Workspace topology:** מבנה ה-monorepo, packages ו-dependency graph (ייצוא מ-Nx/Bit ל-JSON).
  3. **חוזי API וסכמות:** types, OpenAPI, DB schemas.
  4. **סגנון ומוסכמות:** lint, naming, דפוסים.
  5. **דוגמאות מימוש מייצגות** ("slices") של פיצ'ר טיפוסי מקצה לקצה.
  6. **Build & run:** פקודות, env, scripts.
  7. **Test harness:** איך בודקים, ודוגמאות טסטים.
  8. **Knowledge graph / RAG index** (nice-to-have), למשל GraphRAG על כל הריפו.
- **טיפים לחיסכון בטוקנים:** לסכם קבצים ענקיים (חתימות ו-docstrings). להוריד קוד מג'ונרט (`*.d.ts`, JS מקומפל, lockfiles). לחלק גרפי JSON לפי פיצ'ר. **לעבוד באיטרציות:** diff קטן, CI, להחזיר את לוג השגיאה.
- יש גם "upload order" מומלץ לבקשת code-gen בודדת.
